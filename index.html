What is CS50?

CS50 is Harvard University's largest course — and one of the most popular computer science courses in the world.

CS50 (Introduction to Computer Science) is taught by Professor David J. Malan and a team of teaching fellows. It has been running since 2007 and has reached over 4 million learners through its online platform, CS50x on edX.

The course is designed for students with little or no prior programming experience, though experienced programmers also benefit from its breadth — especially the deep dive into C, memory management, and data structures that many bootcamps skip.

What You'll Learn

  • How to think algorithmically and solve problems systematically
  • Fundamentals of programming in C, Python, SQL, HTML/CSS/JS
  • How computers represent and store data (binary, ASCII, memory)
  • Core algorithms: searching, sorting, recursion
  • Essential data structures: arrays, linked lists, hash tables, tries
  • Web development with Flask and relational databases
  • Topics in security, ethics, and artificial intelligence

The Instructor: David J. Malan

Professor Malan is a senior preceptor in Computer Science at Harvard. Known for his energetic lecture style, he makes complex topics accessible through live coding demonstrations, visual metaphors, and real-world analogies. He holds a PhD from Harvard and has been teaching CS50 since 2007.

Course Philosophy

Concepts over syntax CS50 deliberately uses multiple languages (Scratch → C → Python → SQL → JS) so you learn ideas that transfer across languages, not just one language's syntax.

The course follows a "bottom-up" approach for the first half (understanding how computers work at a low level with C) and then moves "top-down" with higher-level languages and frameworks. This dual perspective gives you both depth and practical skills.

CS50 Course Variants

CS50 has expanded into specialized versions for different audiences. All share the same rigorous foundation.

The flagship online course on edX. Free to audit, optional verified certificate. This is the version most self-learners take.

Adapted for high school students preparing for the AP Computer Science Principles exam. Aligned with College Board standards.

CS50 for Lawyers

A variant focused on computational thinking for legal professionals — algorithms, data, and technology in law.

CS50 for Business

Tailored for business professionals who need to understand technology, data, and software development.

A follow-up course exploring artificial intelligence — search, optimization, machine learning, and neural networks.

CS50 Web

A follow-up focused entirely on web programming — deeper Flask, React, Django, and modern web development.

On-Campus vs. Online

Harvard students take CS50 in-person with live lectures, sections (small-group tutorials), and in-person office hours. Online learners get the same lecture recordings, problem sets, and grading tools, but participate asynchronously through Ed discussion boards and virtual office hours.

Key Concepts

Binary

Computers only understand 0s and 1s. Everything — text, images, sound — is encoded in binary. A single binary digit is a bit; 8 bits make a byte.

// The letter 'A' in ASCII
A = 65 = 01000001

// Counting in binary
0 = 0
1 = 1
2 = 10
3 = 11
4 = 100
5 = 101

Scratch Building Blocks

  • Motion — move, turn, go to coordinates
  • Looks — say, think, change costumes
  • Sound — play notes and effects
  • Events — when flag clicked, when key pressed
  • Control — if/else, repeat, forever, wait
  • Sensing — detect mouse, keyboard, collisions
  • Operators — math and logic comparisons
  • Variables — store and manipulate data
  • My Blocks — create custom functions

Recursion

int factorial(int n)
{
    if (n == 0)
    {
        return 1;          // base case
    }
    return n * factorial(n - 1);  // recursive case
}

// factorial(3) = 3 * factorial(2)
//              = 3 * 2 * factorial(1)
//              = 3 * 2 * 1 * factorial(0)
//              = 3 * 2 * 1 * 1 = 6

Week 4 — Memory

Week 4

Pointers, malloc & File I/O

Peek under the hood of your programs. Learn how data lives in memory (RAM), use pointers to access memory addresses directly, allocate memory dynamically with malloc, and read/write files.

Hexadecimal Pointers Strings as Pointers Dynamic Memory malloc / free File I/O Memory Leaks
📝 Pset: Memory — Filter, Recover, Volume

Understanding Pointers

int n = 50;
int *p = &n;    // p stores the address of n

printf("n = %i\n", n);      // 50
printf("p = %p\n", p);      // 0x7fff5fbff6bc (address)
printf("*p = %i\n", *p);   // 50 (value at address)

Dynamic Memory Allocation

int *list = malloc(3 * sizeof(int));
if (list == NULL)
{
    return 1;  // out of memory
}
list[0] = 1;
list[1] = 2;
list[2] = 3;
free(list);  // always free what you malloc!

Problem Sets

  • Filter (Less/More) — Apply grayscale, blur, or edge detection filters to BMP images by manipulating pixels in memory.
  • Recover — Forensically recover deleted JPEG photos from a raw memory card dump.
  • Volume — Adjust the volume of a WAV audio file by modifying amplitude values.
Memory errors are common here Segmentation faults, buffer overflows, and memory leaks appear frequently. Always check return values of malloc, free allocated memory, and use valgrind to detect leaks.

Week 5 — Data Structures

Week 5

Linked Lists, Hash Tables & Tries

Move beyond arrays to more flexible data structures. Build linked lists, implement hash tables for fast lookups, and explore tries for efficient string storage.

Linked Lists Stacks & Queues Hash Tables Hash Functions Tries Abstract Data Types
📝 Pset: Speller (capstone C pset)

Linked List Node

typedef struct node
{
    int number;
    struct node *next;
} node;

// Insert at front
node *list = NULL;
node *n = malloc(sizeof(node));
n->number = 2;
n->next = list;
list = n;

Hash Table

A hash table maps keys to buckets using a hash function. Collisions (two keys mapping to the same bucket) are handled with chaining (linked lists at each bucket).

// Simple hash function for strings
unsigned int hash(const char *word)
{
    return tolower(word[0]) - 'a';
}
// "cat" → bucket 2, "dog" → bucket 3

Problem Set: Speller

The capstone C problem set. Implement a spell checker that loads a dictionary into memory and checks if words in a text file are spelled correctly. Choose your data structure:

  • Hash table — most popular choice, good balance of speed and memory
  • Trie — fastest lookup, but uses more memory
  • Linked list — simplest, but too slow for large dictionaries

Week 6

Programming in Python

C vs Python Comparison

# C (Week 1 Mario)
for (int i = 0; i < height; i++)
{
    for (int j = 0; j < height - i - 1; j++)
        printf(" ");
    for (int j = 0; j < i + 2; j++)
        printf("#");
    printf("\n");
}

# Python equivalent
for i in range(height):
    print(" " * (height - i - 1) + "#" * (i + 2))

Python Features

  • No type declarations — dynamic typing
  • Indentation — whitespace defines code blocks (no braces)
  • Built-in data structures — lists, dicts, sets, tuples
  • Exceptions — try/except for error handling
  • Rich standard library — sys, csv, json, requests

Core SQL Commands

-- Create a table
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT UNIQUE
);

-- Insert data
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');

-- Query data

-- Join tables

Database Design Principles

Why It Matters

Understanding Big O helps you choose the right algorithm for the job. Searching 1 million items with linear search takes up to 1 million steps. With binary search (on sorted data), it takes at most ~20 steps. That difference is the foundation of scalable software.

Data Structures Reference

Data structures are ways of organizing data in memory. Choosing the right one can make your program orders of magnitude faster.

Array

Fixed-size, contiguous memory. O(1) access by index, O(n) insert/delete. Foundation of everything in C.

Linked List

Nodes connected by pointers. O(n) access, O(1) insert/delete at head. Dynamic size, no wasted space.

Stack

Last-In-First-Out (LIFO). Push and pop from the top. Used in function calls, undo operations, parsing.

Queue

First-In-First-Out (FIFO). Enqueue at back, dequeue from front. Used in scheduling, BFS traversal.

Hash Table

Key-value store with O(1) average lookup. Uses a hash function to map keys to buckets. Handles collisions with chaining.

Trie

Tree for storing strings. Each node is a letter. O(k) lookup where k is word length. Used in autocomplete, spell checkers.

When to Use What

NeedBest ChoiceWhy
Fast lookup by indexArrayO(1) random access
Fast lookup by keyHash TableO(1) average case
Prefix search / autocompleteTrieEfficient prefix matching
Dynamic size, frequent insertLinked ListO(1) insert at known position
Undo/redo functionalityStackLIFO matches undo semantics
Task schedulingQueueFIFO ensures fairness

Memory & Pointers

Understanding memory is what separates CS50 graduates from casual coders. This is the hardest but most rewarding part of the course.

Memory Layout

When a C program runs, memory is organized into segments:

SegmentContentsGrows
Text (Code)Your compiled machine instructions—
Global / StaticGlobal variables, string literals—
HeapDynamically allocated memory (malloc)↑ upward
StackLocal variables, function call frames↓ downward

Common Memory Errors

  • Segmentation fault — accessing memory you don't own (null pointer, out of bounds)
  • Memory leak — allocating with malloc but never calling free
  • Buffer overflow — writing past the end of an allocated block
  • Use after free — accessing memory after it's been freed
  • Double free — calling free on the same pointer twice

Debugging Memory with Valgrind

# Compile with debug symbols
make speller

# Check for memory leaks
valgrind --leak-check=full ./speller texts/cat.txt
Always free what you malloc Every malloc call should have a corresponding free. Valgrind is your best friend for finding leaks.

Web Development Stack

Weeks 8–9 introduce the full web development stack you'll use in CS50 and beyond.

How the Web Works

  1. Browser sends an HTTP request to a server (e.g., GET /index.html)
  2. Server processes the request (runs Python/Flask code, queries database)
  3. Server sends back an HTTP response (HTML, JSON, etc.)
  4. Browser renders the response and runs JavaScript

Study Tips & Strategies

CS50 is challenging but absolutely doable. Here are proven strategies from successful students.

📅 Start Psets Early

Begin each problem set the day it's released. They routinely take 2–3x longer than you estimate.

📖 Read the Spec First

Read the entire pset specification before writing any code. Understand requirements fully before implementing.

🦆 Rubber Duck Debug

Explain your code line-by-line out loud (to a duck, a friend, or yourself). You'll often find the bug yourself.

🔍 Debug Systematically

Use printf debugging, debug50, and valgrind. Don't randomly change code hoping it fixes things.

🔄 Rewatch Lectures

It's normal to rewatch lectures, especially Weeks 4 and 5. Malan's explanations get clearer on second viewing.

🤝 Collaborate on Ideas

Discuss approaches with classmates, but write your own code. CS50's academic honesty policy is strict about copying.

When You're Stuck

  1. Re-read the pset specification and lecture notes
  2. Search the Ed forum and Stack Overflow for similar issues
  3. Ask cs50.ai for hints (not full solutions)
  4. Post on Discord or r/cs50 with your specific error
  5. Attend office hours (virtual or in-person)
  6. Take a break — fresh eyes solve bugs faster

Certificate & Grading

CS50x offers a free audit track and an optional verified certificate through edX.

Audit (Free)

  • Access to all course materials
  • Automated grading via check50
  • Community support
  • No certificate, no deadline

Verified Certificate (~$189)

  • Everything in the audit track
  • Official edX/Harvard certificate upon passing
  • Identity verification required
  • Must score 70%+ on labs, problem sets, and final project

Grading Breakdown
